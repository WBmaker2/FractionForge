## 1. 상설 셀프테스트 (`?selftest=1`)

- `init()` 앞에 쿼리스트링 분기. `location.search`에 `selftest`가 있으면 자동 복원·화면 전환을 건너뛰고 테스트 표를 렌더링.
- 10건: 계획서 4절 7건(`normalize 2/4`, `compare 1/3-1/4`, `add 1/2+1/2`, `add 1/4+2/4`, `sub 1-1/3`, `parse 2/4==1/2`, 분모 0·빈 입력) + 대분수 표기(`3/2`→`1과 1/2`) + 문항 정합 2건(`makeCompare` 기호 일치, `makeArith` 답 일치).
- 결과는 표(통과 초록/실패 빨강) + `window.__ffSelfTest = {pass, fail}` 로 노출해 ego-browser에서 판독.
- `file://`에서도 쿼리스트링 동작. 일반 화면 영향 0, 외부 요청 0.

## 2. 채점·상태 리팩터링

- `gradeAnswer(given, q)` → `{ correct, feedback, nextHint }` 반환으로 확장(계획서 124줄 스펙 충족). A/B/C 세 곳의 판정을 이 함수 호출로 교체.
- 활동 A: 오답도 `state.answers`에 `attempts`로 기록하되 점수는 정답 확정 시에만 +1. 결과 화면에 "n번 만에 맞혔어요" 표시 (G4 해소).
- 상태: `phase`+`pos`를 명시 저장하되, `pos`는 "푼 문제 수"(인덱스가 아님). 복원은 `pos` 값이 아니라 **확정 답 목록을 세어** 계산(`resumePosition`)하므로 시도 기록이 섞여도 정확하다. `state.index`는 확정 답 수와 항상 일치 (G2 해소).
- 결과 화면 새로고침 복원: `init()`의 `screen !== 'result'` 제외 조건 제거 (G3 해소).
- 마이그레이션: 기존 저장값에 `phase`가 없으면 answers 역산으로 폴백. 학생 기록이 지워지지 않게 `version`은 1 유지.

## 3. 모바일·접근성 실측

- ego-browser `Emulation.setDeviceMetricsOverride`(375×812, mobile) → 시작/A/B/결과 4화면 스크린샷.
- CSS 토큰 색 조합의 대비(4.5:1) 계산 스크립트로 측정. 미달 토큰이 있으면 진하게 조정.
- 키보드만으로 시작→A 조각 색칠→B 기호 선택→C 입력→결과 왕복. 조각 12개 Tab 부담이 크면 분자 ± 버튼 추가 여부를 판단.
- `Emulation.setEmulatedMedia`로 `prefers-reduced-motion: reduce` → 펄스 링 `animation: none` 확인.
- 콘솔 에러: ego `page.on` 미지원 → `Runtime.enable` + `Log.enable` CDP 수집(또는 `window.__ffErrors` 심기) 후 전체 플로우 재실행, 0건 확인.
